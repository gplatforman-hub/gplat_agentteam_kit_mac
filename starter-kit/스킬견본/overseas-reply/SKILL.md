# 해외답장

> 일을 시작하기 전에 workspace/memory/facts.md 를 읽어 내 이름·팀 이름을 확인하고 그 값을 쓴다.

[이 스킬이 하는 일]
해외 고객의 영문 메일(견적 요청·기술 문의·클레임)을 읽고
① 영문 답장 초안 ② 내가 읽을 한글 요약 ③ 확인 필요 목록 을 만든다. 보내지 않는다.

[독자가 누구인지]
답장의 독자는 해외 바이어(구매·품질 담당)다. 짧고 정확한 답을 원한다.
한글 요약의 독자는 나와 팀장이다. "무엇을 물었고, 무엇을 답했고, 무엇을 사람이 정해야 하나"를 본다.

[Step 0 — 착수 전 확인할 것]
  1. ⭐ 답할 메일 (파일 또는 붙여넣기). 메일이 여러 통이면 어느 것인지 묻는다.
  2. ⭐ 근거 문서 — 기본은 실습자료/제품사양서.md. 기술FAQ.md 는 참고만 한다.
  3. 내가 승인한 가격·생산 기간·보상 방침이 있는지 — 없으면 그 칸은 "확인 필요"
  → 1번이 없으면 시작하지 않는다.

[순서]
1. 메일에서 질문을 하나씩 뽑아 표로 만든다 — # | 질문(원문) | 한글 뜻 | 근거 문서의 답 | 근거 위치
2. 근거 문서에 답이 없거나 "미정"이면 답을 만들지 않고 "확인 필요" 로 둔다.
3. 기술FAQ 와 사양서가 다르면 사양서를 따르고, 다른 점을 확인 필요 목록 맨 위에 적는다.
4. 표를 바탕으로 영문 답장을 쓴다. 답할 수 있는 것은 답하고, 확인 중인 것은
   "We are confirming this and will get back to you by [date]." 처럼 날짜 칸을 비워 둔다.
5. 클레임 메일이면: 사과와 확인 절차(사진·로트 번호 요청)까지만 쓴다.
   원인 단정 · 보상 · 교환 약속은 쓰지 않는다 — 팀장 승인 사항으로 확인 필요에 올린다.
   사양서에 있는 사용 조건(예: 사용 온도)은 "참고로 안내" 할 수 있지만, 그것이 원인이라고 쓰지 않는다.
6. 상대가 쓴 사실을 바꿔 말하지 않는다. (예: "깨졌다고 보고됨" 을 "도착할 때 깨져 있었다" 로 바꾸면 원인을 단정하는 셈)
7. 사양서의 "미정" 옆에 적힌 예정 일정(예: 결과 예정 월)도 바이어에게 알리기 전에 확인 필요에 올린다.

[영문 답장 모양]
- 제목은 Re: 원래 제목
- 첫 줄 감사 → 질문 번호 순서대로 짧게 답 → 확인 중인 것과 회신 날짜 칸 → 맺음
- 문장은 짧게. 과장 표현(best, perfect, guaranteed) 쓰지 않는다.
- 서명은 facts.md 의 내 이름·팀 이름을 쓴다. 비어 있으면 [이름] / [팀 이름] 칸으로 남긴다. 회사 줄은 Gaon Living (fictional).

[절대 금지]
- 가격·할인·MOQ 예외·생산 기간·인증·보상을 지어내지 않는다. 근거 문서나 내가 준 값만 쓴다.
- 메일을 보내지 않는다. 파일까지만.
- 실제 고객사 메일을 받으면 "회사명·사람 이름·연락처를 지운 사본으로 해 주세요" 로 돌려준다.
  (실습자료의 가상 바이어는 그대로 써도 된다)
