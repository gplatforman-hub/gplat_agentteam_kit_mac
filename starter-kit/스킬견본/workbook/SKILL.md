# 교육 안내·워크북

> 일을 시작하기 전에 workspace/memory/facts.md 를 읽어 내 이름·팀 이름·로고 글자·색 4개를 확인하고 그 값을 쓴다.

[이 스킬이 하는 일]
교육 요청 메모를 받아 ① 교육 안내문과 ② 참가자가 손에 쥐는 워크북(A4)을 만든다.

[독자가 누구인지]
안내문의 독자는 참가자와 그 팀장 — "언제·어디서·무엇을 준비하나"를 본다.
워크북의 독자는 교육장의 참가자 — 읽기보다 쓰면서 따라간다.

[Step 0 — 착수 전 확인할 것]
요청 메모를 먼저 읽고, 없는 것만 한 번에 묻는다.
  1. ⭐ 교육 이름과 대상 (직무·인원)
  2. ⭐ 일시·장소
  3. ⭐ 다룰 내용 목록 (메모의 "내용"·"워크북에 넣을 것")
  4. 준비물
  5. 진행자 (이름 대신 역할로)
  → 3번이 없으면 시작하지 않는다. 교안이 따로 없어도 메모의 내용 목록으로 만든다.

[① 안내문 구조]
제목 · 한 줄 목적 · 일시/장소/대상/준비물 표 · 다루는 내용 3~5줄 · 문의처(역할)

[② 워크북 구조]
- 표지 → 내용 목록의 항목마다 한 챕터 → 마무리(오늘 배운 것 3줄 쓰는 칸)
- 챕터마다: 핵심 설명 3~5줄 + 따라 쓰는 칸(빈칸 채우기 또는 표) 1개 이상
- 메모에 연습 사례가 있으면 사례마다 한 쪽: 상황 · 내가 할 말을 쓰는 칸 · 체크 포인트
- 판형: A4 세로 794px x 1123px, @page{size:A4;margin:0}. 쪽 머리 띠는 기본 색, 쓰는 칸은 옅은 색 배경
- 서체 "Noto Sans KR","Malgun Gothic",sans-serif. 인터넷에서 불러오지 않는다. 자바스크립트는 쓰지 않는다

[절대 금지]
- 메모에 없는 일정·장소·강사 이름·설문 문항을 지어내지 않는다. 모르면 "확인 필요".
- 참가자 실명·연락처를 넣지 않는다.

[저장]
workspace/결과물/<날짜>_<교육이름>_안내문.md
workspace/결과물/<날짜>_<교육이름>_워크북.html

[끝낼 때]
저장한 파일 경로와 '확인 필요' 항목만 모아서 알려 주고, "html 을 열고 ⌘+P → PDF로 저장" 을 안내한다.
