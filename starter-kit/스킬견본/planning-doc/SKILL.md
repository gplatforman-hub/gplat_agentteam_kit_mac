# 결론 먼저 기획서

> 일을 시작하기 전에 workspace/memory/facts.md 를 읽어 내 이름·팀 이름·로고 글자·색 4개를 확인하고 그 값을 쓴다.

[이 스킬이 하는 일]
새 일을 제안하는 기획서, 또는 이미 쓴 보고서를 "결론 먼저" 구조로 만든다.

[Step 0 — 착수 전 확인할 것]
  1. ⭐ 무엇을 하자는지 한 줄
  2. 보고 대상
  3. 목표 숫자 (없으면 "가정"으로 표시)
  4. 기간 · 예산 범위
  5. 고쳐 쓸 원문이 있으면 그 파일

[기획서 구조]
1. 한 줄 결론 — 무엇을 언제까지 얼마로 하자
2. 왜 지금 — 배경 2~3줄, 숫자 근거
3. 목표 — 숫자로
4. 방법 — 단계 3~5개
5. 일정 — 표: 단계 | 할 일 | 담당(역할) | 시작 | 끝 | 산출물
6. 필요한 것 — 사람 · 돈 · 도구
7. 위험과 대응 — 표 2~3줄
8. 결정 요청 — 상사가 정해야 할 것

[원문을 결론 먼저로 바꿀 때]
- 원문 문단마다 [결론]/[근거]/[배경] 꼬리표를 먼저 붙여 보여준다.
- 결론 문단을 맨 앞으로 옮기고, 근거는 숫자가 있는 것부터.
- 원문의 숫자·고유명사는 하나도 빼지 않는다. 원문 파일은 고치지 않고 새 파일로.

[절대 금지]
- 근거 없는 목표 숫자·기대 효과를 지어내지 않는다. "가정" 또는 "확인 필요".
- 대폭 · 획기적인 · 혁신적인 · 극대화 · 다양한 · 효율적인 · 최적의 를 쓰지 않는다.

[저장]
workspace/결과물/<날짜>_<주제>_기획서.md

[끝낼 때]
저장한 파일 경로와 '확인 필요' 항목만 모아서 알려 준다.
