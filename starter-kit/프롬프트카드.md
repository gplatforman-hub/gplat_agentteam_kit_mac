## Claude Code 사용법 (교안 「Claude Code 사용법」 쪽)

**채팅과 Code**

|  | 채팅 (claude.ai) | Claude Code (Code 탭) |
|---|---|---|
| 일하는 곳 | 대화창 안 | 내가 고른 폴더 안 (내 PC) |
| 파일 | 내가 올리고, 결과는 내가 복사해서 옮김 | 폴더의 파일을 직접 읽고, 새로 만들고, 고침 |
| 프로그램 실행 | 채팅 안의 별도 공간에서만 (내 PC 는 건드리지 못함) | 내 PC 에서 명령을 실행 (예: py 점검.py, git 저장, 메일 도구) |
| 기억 | 채팅의 기억·프로젝트 기능 안에 남음 (내 PC 파일로는 남지 않음) | 규칙표·스킬·직원을 폴더에 파일로 남김 → 새 세션도 그 파일을 읽고 같은 방식으로 일함 |
| 안전장치 | — | 파일을 바꾸기 전 허락 창 · 권한 모드 · git 저장 지점(되돌리기) |
| 잘하는 일 | 생각 정리, 글 다듬기, 질문·설명 | 여러 파일을 다루는 반복 업무, 결과를 파일로 남기는 일, 메일·캘린더·슬랙 같은 도구 연결 |

**로그인은 언제 하나요**

| 어디서 | 로그인 | 모델 |
|---|---|---|
| 터미널 · 터미널 패널에 명령어 넣기 | 필요 없음 — Claude 가 아니라 컴퓨터가 바로 실행 | 해당 없음 |
| 한 줄 설치 3단계 「Claude Code 로그인 창」 | **한 번** — 브라우저에서 claude.ai 유료 계정으로 로그인·승인 (슬랙 직원용) | 서버 설정 (기본 Sonnet) |
| Code 탭 대화창 | Claude 앱에 로그인돼 있으면 끝 | 입력칸 오른쪽 아래 (M1) |

설치 때 한 번 로그인해 두었으므로, 이 PC 에서는 나중에 터미널에서 `claude` 를 쓸 때도 다시 로그인할 필요가 없습니다 (어느 폴더에서든 같습니다). 다른 PC 에서는 처음 한 번 로그인합니다. 설치 때 건너뛰었다면 환경점검의 「Claude Code 로그인」 줄 안내(`claude auth login`)를 터미널 창에.

**Code 탭 화면** (번호는 교안 그림)

| 번호 | 이름 | 하는 일 |
|---|---|---|
| ① | 새로 만들기 | 새 세션(새 대화). 단축키 ⌘+N. 카드의 🆕 표시는 여기서 시작 |
| ② | 세션 목록 | 폴더별로 지난 대화가 쌓입니다. 눌러서 다시 열면 이어서 일할 수 있습니다 (카드의 ↩ 표시) |
| ③ | 채팅 ↔ Code | 말풍선은 채팅, </> 는 Code. 오늘은 Code 에 둡니다 |
| ④ | 입력칸 | + 파일·그림 넣기(끌어다 놓아도 됨) · / 를 치면 명령어·스킬 목록 · @ 를 치면 파일 고르기 |
| ⑤ | 모델 · 생각 수준 | 누르면 모델과 「생각 수준(Effort)」을 고릅니다. 오늘은 Sonnet (M1). 단축키 ⌘+Shift+I · ⌘+Shift+E |
| ⑥ | 권한 모드 | 클로드가 무엇을 묻고 할지 정합니다 — 아래 표. 단축키 ⌘+Shift+M |
| ⑦ | 오른쪽 위 도구줄 | 오른쪽 패널 열고 닫기 · >_ 터미널(control+` [확인 필요: 맥 단축키]) · 변경 내용 보기(⌘+Shift+D) · 브라우저(⌘+Shift+B) · 폴더 열기 |
| ⑧ | 환경 | 이 컴퓨터(내 PC 에서 실행) · 열린 폴더 · git 브랜치 · Remote Control(다른 기기에서 이 세션 보기 — 수업에서는 끔) |
| ⑨ | 컨텍스트 · 커넥터 | 컨텍스트 % = 이 대화가 얼마나 찼는지. 높아지면 새 세션이나 /compact. 커넥터 = 연결된 Gmail·캘린더 등 |
| ⑩ | 결과물 · 변경 사항 | 이 대화에서 만든 파일, 바뀐 파일과 +/- 줄 수. 누르면 무엇이 바뀌었는지 보입니다. 키트가 답마다 git 저장을 하므로 「커밋」 버튼은 누르지 않아도 됩니다 |
| ⑪ | 한 일 요약 | 답 중간의 「편집함 · 읽음 · 생성됨」 줄. 「변경 사항 보기」 로 고친 곳을 확인합니다 |

**권한 모드**

| 모드 | 하는 일 | 언제 |
|---|---|---|
| 수동 (Manual) | 파일을 바꾸거나 명령을 실행하기 전에 매번 묻습니다 | ⭐ 수업 기본값 (M1) |
| 편집 허용 (Accept edits) | 파일 만들기·고치기는 묻지 않고, 그 밖의 명령은 묻습니다 | 익숙해진 뒤 |
| 계획 (Plan) | 파일을 읽고 살펴본 뒤 계획만 내놓습니다. 파일은 고치지 않습니다 | ⭐ 큰 일 시키기 전 |
| 자동 (Auto) | 묻지 않고 진행하되, 위험해 보이는 일은 막습니다. 보일 때만 고를 수 있습니다 | 집에서 · 익숙해진 뒤 |
| 권한 무시 (Bypass) | 아무것도 묻지 않습니다. 설정에서 따로 켜야 보입니다 | 쓰지 않습니다 |

**치트키** (⭐ = 수업에서 씀)

|  | 하고 싶은 일 | 이렇게 |
|---|---|---|
| ⭐ | 계획부터 보고 시키기 | ⑥ 권한 모드 → 계획 (⌘+Shift+M). 계획을 읽고 괜찮으면 진행. 카드 끝의 「먼저 계획을 보여 줘」 와 같은 효과 |
| ⭐ | 멈추기 | Esc — 엉뚱한 쪽으로 가면 바로 멈추고 다시 말합니다 |
| ⭐ | 새 대화 | ⌘+N 또는 ① 새로 만들기. 모듈이 바뀌면 새 대화 |
| ⭐ | 파일 콕 집어 주기 | @ + 파일 이름 앞글자 → 목록에서 고르기 (예: @facts) |
| ⭐ | 스킬 부르기 | / 를 치면 목록이 나옵니다 → 스킬 이름 고르기 (예: /meeting-notes). 「회의록 스킬로 정리해 줘」 처럼 말로 해도 됩니다 |
|  | 파일·그림 넣기 | ④ 의 + 또는 끌어다 놓기 (그림, PDF 등) |
|  | 대화가 길어졌을 때 | /compact — 지금까지를 요약해 두고 이어갑니다. 주제가 바뀌었으면 새 대화가 더 낫습니다 |
|  | 무엇이 자리를 차지하나 | /context 또는 ⑨ 컨텍스트를 누르기 |
|  | 터미널 · 변경 · 브라우저 | control+` [확인 필요: 맥 단축키] · ⌘+Shift+D · ⌘+Shift+B |
|  | 답 속 명령어 실행 | 명령어 상자 오른쪽 ▷ — 허락 창 없이 바로 실행되니 읽고 누르기. 버튼이 없으면 「실행할 명령어는 한 줄씩 명령어 상자로 따로 보여 줘」 |
|  | 단축키 전체 보기 | ⌘+/ |

메뉴 이름·단축키는 앱 버전에 따라 조금 다를 수 있습니다. 전체 단축키는 `⌘+/`.

## 용어와 폴더 (교안 「용어와 폴더」 쪽)

**파일 종류**

| 확장자 | 뜻 | 여는 법 | 내가 만져도 되나 |
|---|---|---|---|
| `.md` | 마크다운. 제목(#)·목록(-)을 쓴 글자 파일. 규칙표·스킬·직원·회의록 같은 결과물이 모두 .md | 텍스트 편집기, 또는 Code 탭 답 속의 파일 링크 | 내 것(규칙표·스킬·결과물)은 됨. 고칠 때는 Claude 에게 시키는 게 안전 |
| `.command` | 더블클릭하면 터미널이 열리고 안에 적힌 명령을 실행하는 메모 (윈도우의 `.bat` · M8 「버튼 뒤의 명령어」) | 더블클릭 = 실행 · control + 클릭 → 다음으로 열기 → 텍스트 편집기 = 내용 보기 | 내용 보기만 |
| `.sh` | 셸 스크립트. `.command` 가 부르는 실제 일꾼 (윈도우의 `.ps1`) | — | 고치지 않음 |
| `.py` | 파이썬 프로그램 (`점검.py`, 메일·블로그 도구) | Claude 나 .command 가 실행 | 고치지 않음 |
| `.env` | 열쇠·비밀번호를 적어 두는 파일. 이름 없이 점으로 시작합니다 | `슬랙열쇠_넣기.command` · `메일_연결.command` 이 만들고 채움 | 열어 보지도, 보내지도, 캡처하지도 않음 |
| `.example` | 견본. `.env.example` → `.env`, `facts.예시.md` → `facts.md` 처럼 복사해 쓰는 원본 | — | 견본은 그대로 둠 |
| `.json` | 프로그램 설정 (예: `.claude/settings.json`) | — | 고치지 않음 |
| `.html` | 브라우저로 여는 화면 (`환경점검_결과.html`, 이 교안, 보고서) | 더블클릭 | 됨 |
| `.xlsx` · `.csv` | 엑셀 파일 · 쉼표로 칸을 나눈 표 | 엑셀 | 실습자료 원본은 읽기만 |

**폴더·파일 이름 — 이것만 지킵니다**

1. 파일 확장자를 보이게 켭니다 — Finder 메뉴 「Finder → 설정 → 고급 → 모든 파일 확장자 보기」. 꺼져 있으면 `메모.md` 가 실제로는 `메모.md.txt` 일 수 있고, 그러면 Claude·직원이 .md 로 읽지 못합니다. 키트의 `_예시_직원.md.txt` 는 직원으로 읽히지 않게 일부러 .txt 를 붙인 것입니다
2. 점(.)으로 시작하는 폴더·파일 — `.claude` · `.git` · `.env` 는 안 보일 수 있습니다. Finder 에서 `⌘ + Shift + .` 을 누르면 보입니다. 보이게 해도 고치지 않습니다
3. 스킬 이름은 영어 소문자·숫자·하이픈 — 폴더 이름과 머리말의 `name` 을 똑같이 `meeting-notes` 처럼 씁니다. 한글로 부르는 말(「회의록」)은 `description` 에 씁니다. 파일 이름은 대문자로 정확히 `SKILL.md`
4. 키트의 파일·폴더 이름은 바꾸지 않습니다 — .command·훅·직원이 이름으로 찾습니다 (예: `workspace/memory/facts.md`, `자동시작_켜기.command`, `.claude`). 내 결과물의 이름은 자유입니다
5. 띄어쓰기가 들어간 경로는 "따옴표"로 감쌉니다 — 카드의 명령어 경로에 따옴표가 있는 이유입니다
6. `.env` 와 열쇠는 내 PC 에만 — 남에게 보내거나 캡처하지 않습니다. 키트의 `.gitignore` 에 적혀 있어 git 저장과 공개 저장소에도 올라가지 않습니다
7. 원본은 읽기만, 결과는 따로 — 원본은 `실습자료`, 결과는 `workspace/결과물`. `CLAUDE.md` 에 적힌 규칙이라 Claude 도 이렇게 합니다

[Step 0 — 먼저 파일을 살핀다 (계산하기 전에)]
  파일 이름 · 시트 · 행 수 · 열 이름 · 빈 칸 수 · 중복 행 수를 표로 보여준다.

- 합계·증감률은 가능하면 엑셀 수식으로 넣어, 숫자를 바꾸면 따라 바뀌게 한다.

[결과물]

[검산 — 끝내기 전에 반드시]
결과 표의 숫자를 원본에서 다시 계산해 "결과 숫자 | 다시 계산한 숫자 | 일치" 표로 확인한다.

[요약 세 줄]
가장 큰 것 · 가장 많이 변한 것 · 눈여겨볼 것 (이상치·빈 달)

[절대 금지]

- 회사 실제 매출 파일을 받으면 "비식별로 바꾼 사본으로 해 주세요" 한 줄로 돌려준다.

[기존 스킬 처리 — 이 줄을 빼면 스킬이 두 개가 된다]

```

"메일을 볼 때는 mail 스킬을 열고 시작한다" 한 줄을 넣어줘. --- 부분은 건드리지 말 것.

그다음 py -3.14 mail/mail_check.py 를 실행해서 결과 한 줄을 그대로 보여줘.

본문은 보여주지 말고, 📌문의 표시가 붙은 게 있으면 그 건만 회신 초안을 workspace/결과물/ 에 만들어줘.

> 📌 **메일 한 통을 끝까지** — 목록엔 본문 앞 400자만. `3번 메일 전체 읽고 요점이랑 요청 사항 정리해 줘` 처럼 번호로 시키면 `mail_read.py --full 3` 으로 끝까지 읽습니다. 첨부는 이름만.

### B-3 — 메일에서 일정 뽑아 캘린더에 넣기

> B-1(캘린더)과 B-2(메일)가 먼저 돼 있어야 합니다. 처음엔 **후보 표만** 받고, 내가 고른 것만 등록합니다.

```
최근 메일에서 일정을 찾아 구글 캘린더에 넣으려고 해.

1. py -3.14 mail/mail_read.py --since [2026-10-21] --json 으로 메일을 읽어.
2. 날짜가 적힌 약속(회의·미팅·마감·행사)만 골라 "일정 후보 표" 로 보여 줘.
   칸: 번호 · 메일 제목 · 보낸 사람 · 날짜 · 시간 · 장소 · 근거 문장(메일에서 그대로 한 줄)
   날짜·시간이 메일에 없으면 [확인 필요] 로 두고 추측하지 마.
3. 여기서 멈추고 내가 번호를 고를 때까지 기다려. 아무것도 등록하지 마.
4. 내가 "1, 3 등록" 처럼 고르면 그 건만 구글 캘린더에 넣어.
   제목 앞에 [AI] 를 붙이고, 설명란에 메일 제목과 근거 문장을 적어.
   [확인 필요] 가 남은 건은 등록하지 말고 나에게 다시 물어봐. 참석자 초대는 하지 마.
5. 등록한 일정의 날짜·시간·제목을 표로 보여 줘.
```

**이러면 정상** — 처음엔 후보 표만 나오고 멈춥니다. 번호를 고르면 그 건만 캘린더에 `[AI] …` 로 들어갑니다.
캘린더 허락 창이 뜨면 무엇을 등록하는지 읽고 허락합니다. 잘못 들어간 일정은 캘린더에서 `[AI]` 로 찾아 직접 지웁니다.

### B-4 — 답장 메일 초안 (보내기는 사람이)

```
[3번 메일] 에 답장 초안을 써 줘.

1. py -3.14 mail/mail_read.py 로 그 메일 본문을 읽고, 상대가 묻거나 요청한 것을 세 줄로 정리해 줘.
2. 답장 초안을 workspace/결과물/[20261028]_답장초안_[상대].md 로 저장해 줘.
   - 첫 줄에 용건, 다섯 줄 안팎, 말투는 [정중하게]
   - 내가 정해야 하는 것(날짜·금액·가능 여부)은 [확인 필요] 로 두고 지어내지 마
3. py -3.14 mail/mail_send.py 를 --approved 없이 실행해 보내기 전 미리보기만 보여 줘. 여기서 멈춰.
4. 내가 "임시보관함" 이라고 하면 py -3.14 mail/mail_draft.py 로 내 메일함 임시보관함에 넣어 줘.
메일은 보내지 마.
```

**이러면 정상** — 요청 정리 세 줄, 초안 파일, 그리고 "보내지 않았습니다" 가 붙은 미리보기가 나옵니다.
`[확인 필요]` 를 내가 채운 뒤, 초안을 복사해 **내 메일 앱에서 직접** 보냅니다.
"임시보관함" 이라고 하면 `DRAFT: 임시보관함 / 제목` 한 줄 — 메일 앱(휴대폰도) 임시보관함에서 고쳐 바로 보냅니다. 넣을 때마다 한 통씩 생기니 두 번 시키지 않습니다.

### B-5 — 네이버 블로그 임시저장 (모든 트랙)

**네이버 캘린더 연결 (선택 · 5분)** — 구글 캘린더는 B-1 커넥터, 네이버 캘린더는 키트 도구. 메일과 같은 네이버 앱 비밀번호를 같이 쓸 수 있습니다.

1. `캘린더_연결.command` 더블클릭 → 「메일에 연결한 네이버 계정 … 같이 쓸까요?」 면 `y`, 아니면 아이디 · 앱 비밀번호(별표)
2. `OK: 네이버 캘린더 … — 캘린더 N개 (…) · 이번 주 일정 N개` 면 끝 (직원용 스킬도 저절로 들어감)
3. Code 탭 새 세션 · 슬랙 `새 대화` 뒤 「이번 주 네이버 캘린더 일정 알려 줘」
4. 넣기: 「네이버 캘린더에 11월 10일 오후 2시 거래처 미팅 1시간 넣어 줘」 → 미리보기 → 「응」. 고치기·지우기는 네이버 캘린더 앱에서 직접

**블로그 연결 (처음 1회)** — 메일 연결과 따로입니다. 터미널 창 또는 Code 탭 터미널 패널에 한 줄 붙여넣기. 크롬 창이 뜨면 **내가 직접** 로그인합니다(도구는 비밀번호를 넣지 않습니다).

```
py -3 "~/AgentOffice/01_KIT/starter-kit/naver-blog/naver_draft.py" login --blog-id 내블로그아이디
```

`내블로그아이디` 는 내 블로그 주소 `blog.naver.com/이아이디` 의 그 부분입니다. 5분 안에 로그인하면 되고, `[OK] 세션 백업 저장 완료` 와 `로그인 완료 (영구 쿠키)` 가 나오면 끝. 아이디도 이때 기억해서 다음부터는 묻지 않습니다. 그다음 Code 탭에서:

```
네이버 블로그 글을 임시저장함에 넣으려고 해.

1. [workspace/결과물/ 의 주간보고 .md] 를 재료로 블로그 원고를 써 줘.
   제목 1개, 소제목 2~3개, 1,000자 안팎. 재료에 없는 숫자·사례는 지어내지 말고 [확인 필요].
   workspace/결과물/[20261028]_블로그원고.md 로 저장하고 먼저 보여 줘. 여기서 멈춰.
2. 내가 "임시저장" 이라고 하면
   py -3 naver-blog/naver_draft.py check 로 로그인이 살아 있는지 보고,
   py -3 naver-blog/naver_draft.py draft --title "[제목]" --body-file workspace/결과물/[20261028]_블로그원고.md
   로 임시저장함에 넣어 줘.
3. 발행(publish)은 하지 마. 결과 한 줄만 보여 줘.
```

**이러면 정상** — 원고를 먼저 보여 주고 멈춥니다. "임시저장" 이라고 하면 크롬이 잠깐 떴다 닫히고 `[OK]` 한 줄이 나옵니다.
네이버 블로그 → 글쓰기 → 임시저장 글에서 확인하고, 발행은 내가 직접 합니다.
🔒 `naver-blog/.naver-state.json` 은 로그인 열쇠입니다. 남에게 주거나 올리지 않습니다. 회사 블로그는 쓰지 않습니다.

### B-6 — 슬랙에서 업무 시키기 — 메일·일정·블로그 (B-1~B-5 가 된 뒤)

> 슬랙 쪽에 앱을 연결하지 않아도 됩니다. 슬랙 서버가 노트북의 연결(B-1·B-2·B-5)을 그대로 이어받습니다. 연결한 뒤에는 슬랙에 `새 대화` 만 보내면 됩니다(서버를 다시 켤 필요 없음). 노트북이 켜져 있어야 합니다.

```
문서대리 불러서 오늘 들어온 메일 확인하고, 일정 후보 표랑 답장이 필요한 메일 목록을 보여 줘. 등록·발송은 하지 말고 멈춰.
```

| 하고 싶은 일 | 슬랙에 보낼 말 (예) | 되나 |
|---|---|---|
| 메일 목록 | `문서대리 불러서 최근 메일 5통 보여 줘` | ✅ |
| 한 통 전체 읽기 | `3번 메일 전체 읽고 요점이랑 요청 사항 정리해 줘` | ✅ 첨부는 이름만 |
| 답장 초안 | `3번 메일 답장 초안 써 줘. 정할 것은 [확인 필요] 로` | ✅ 파일까지 — 보내기는 내 메일 앱에서 |
| 일정 후보 → 등록 | `오늘 메일에서 일정 후보 표 보여 줘 → 다음 메시지로 1, 3 등록` | ✅ 고른 것만 [AI] 로 |
| 임시보관함에 넣기 | `3번 메일 답장 초안 써서 임시보관함에 넣어 줘` | ✅ 보내지 않음 — 메일 앱 임시보관함에서 고쳐 직접 보내기 |
| 블로그 원고 | `블로그 원고 써 줘. 주제: 가을 기획전. workspace/결과물/20261028_블로그_가을기획전.md 로 저장하고 먼저 보여 줘` | ✅ |
| 블로그 임시저장 | `임시저장해 줘` | ✅ 아이디는 블로그 연결 때 기억한 것 |
| 네이버 캘린더 보기 | `이번 주 네이버 캘린더 일정 알려 줘` | ✅ 캘린더_연결.command 뒤 |
| 네이버 캘린더 넣기 | `네이버 캘린더에 금요일 오전 10시 팀 회의 1시간 넣어 줘` | ✅ 미리보기 → 「응」 하면 넣음 |
| 메일 발송 · 블로그 발행 | — | ⛔ 하지 않습니다 — 사람이 직접 |

**슬랙에서 시킬 때 다섯 가지**

1. **노트북은 켜 둡니다** — 슬랙 직원은 노트북에서 일합니다. 절전·종료면 대답이 없습니다.
2. **연결·스킬을 바꿨으면 새 대화** — 메일·캘린더·블로그 연결, 스킬 추가는 슬랙에 새 대화 만 보내면 반영됩니다. 서버를 다시 켜는 건 직원 추가·이름 변경·슬랙 열쇠 교체 때뿐입니다. 연결해 뒀는데 슬랙 직원이 「캘린더 허가가 없다」「도구가 없다」 고 하면 예전 대화가 이어지는 것입니다 — `새 대화` 를 보내고, 그래도 같으면 `자동시작_켜기.command`.
3. **파일 이름은 매번 새로** — 슬랙에서는 이미 있는 파일을 덮어쓰는 일이 막혀 있습니다. 날짜·주제를 넣어 새 이름으로 시킵니다.
4. **직원·스킬 고치기는 Code 탭** — B-2 처럼 .claude 안을 고치는 일은 슬랙에서 막혀 있습니다. 노트북 Code 탭에서 하고, 슬랙에는 새 대화.
5. **슬랙에서 '도구를 새로 만들었다' 고 하면** — 슬랙 직원도 새 파일은 만들 수 있습니다. 새 프로그램을 만들었다고 하면 노트북 Code 탭에서 「방금 생긴 mail/새파일.py 가 무슨 일을 하는지, 보내기·삭제가 들어 있는지 확인해 줘」 로 한 번 봅니다.

> 슬랙의 직원은 대화를 시작할 때 연결을 읽습니다. 연결을 새로 했다면 슬랙에 `새 대화` 를 먼저 보냅니다.

### C-1 — 고친 것을 쌓는 공책

규칙:

- 이유를 지어내지 말 것 — 지어낸 이유가 규칙이 되면 계속 잘못된 결과물이 나온다

### C-2 — 2번 반복되면 먼저 묻게

workspace/memory/facts.md 에 "승격 규칙" 을 추가해줘. 아래를 그대로 넣어줘.

## 승격 규칙 — 2번이면 묻는다 (C-2)

규칙:

### C-3 — ○ 하면 스킬까지 고쳐 넣게

```
workspace/memory/facts.md 에 "승격 실행" 을 추가해줘. 아래를 그대로 넣어줘.
