# 네이버 캘린더 (naver-calendar)

## 언제 쓰나

대표가 **네이버** 캘린더 일정을 묻거나, 네이버 캘린더에 일정을 넣어 달라고 할 때.
구글 캘린더는 이 스킬이 아니라 커넥터로 한다. "캘린더" 라고만 하면 「네이버요, 구글이요?」 하고 묻는다.
스크립트는 `naver-calendar/` 폴더에 있고, 실행은 **스타터킷 루트에서** `py -3 naver-calendar/스크립트.py …` 형태로 한다 (경로는 슬래시 `/`).

| 대표의 말 | 실행 |
|---|---|
| "네이버 캘린더 연결됐어?", "점검" | `py -3 naver-calendar/cal_check.py` |
| "오늘 일정" | `py -3 naver-calendar/cal_read.py --today` |
| "이번 주 일정" | `py -3 naver-calendar/cal_read.py` |
| "앞으로 2주" | `py -3 naver-calendar/cal_read.py --days 14` |
| "11월 10일~14일" | `py -3 naver-calendar/cal_read.py --from 2026-11-10 --to 2026-11-14` |
| "○일 ○시에 ○○ 넣어줘" | `cal_add.py` **--approved 없이** → 미리보기를 보여 주고 「넣을까요?」 |
| "넣어" (미리보기를 본 뒤 명시적 지시) | 같은 명령에 `--approved` |

`--json` 을 붙이면 JSON 으로 나온다 (주간 보고·일정표를 만들 때).

## 순서

### 1. 점검 (처음, 또는 오류가 날 때)

`OK: 네이버 캘린더 … — 캘린더 N개 (…) · 이번 주 일정 N개` 면 된 것.
`FAIL:` 이나 `[calendar] …` 가 나오면 그 줄의 "→ 해결" 을 대표에게 그대로 전한다.
`.env 가 아직 없습니다` 면 **캘린더_연결.command 을 더블클릭하라고만** 안내한다. 아이디·비밀번호를 대신 묻지 않는다.

### 2. 보기

- 결과는 **날짜(요일) 시각 · 제목 · [캘린더]** 한 줄씩 그대로 전한다. 없는 일정을 지어내지 않는다.
- 「네이버 예약」 캘린더는 네이버 예약 서비스가 만든 것이다. 묻지 않으면 내 캘린더 위주로 정리한다.

### 3. 넣기 — 반드시 두 번에 나눈다

1. 대표의 말에서 제목 · 날짜 · 시각 · 길이(모르면 60분) · 장소를 뽑는다. 날짜가 애매하면("다음 주 화요일") 실제 날짜로 바꿔 **확인을 받는다**.
2. `--approved` **없이** 실행해 `PREVIEW:` 줄을 보여 주고 「이대로 넣을까요?」 묻는다.
3. 대표가 "넣어", "응" 처럼 분명히 승인하면 같은 명령에 `--approved` 를 붙여 실행한다. `ADDED: … (다시 읽어 확인함)` 이 나와야 넣은 것이다.

```
py -3 naver-calendar/cal_add.py --title "거래처 미팅" --start "2026-11-10 14:00" --minutes 60 --location "본사 3층"
py -3 naver-calendar/cal_add.py --title "창립기념일" --all-day 2026-11-12
```

## 규칙

- **고치기·지우기는 하지 않는다.** 그런 도구도 없다. "지워 줘" 라고 하면 네이버 캘린더 앱에서 직접 하시라고 안내한다.
- 승인 없이 `--approved` 를 붙이지 않는다. 한 번 승인은 그 일정 하나에만 해당한다.
- 비밀번호·`.env` 내용을 묻거나 화면에 찍지 않는다.
- 캘린더 도구를 새로 만들지 않는다. 안 되면 오류 줄을 그대로 전한다.
- 다른 사람이 들어간 일정(참석자 초대)은 만들지 않는다. 제목·시각·장소·메모만.
