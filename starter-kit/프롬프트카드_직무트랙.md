## 마케팅 트랙

### T-마케팅-1 — 블로그 스킬 만들기 (제품·행사 안내 글)

```
.claude/skills/blog/SKILL.md 로 '블로그' 스킬을 만들어줘. (name: blog)
먼저 workspace/memory/facts.md 를 읽고 팀 이름을 확인해줘. 아래 내용을 SKILL.md 에 담아줘.

[이 스킬이 하는 일]
제품·행사·캠페인을 알리는 블로그 글 초안을 쓴다. 게시하지 않는다.

[독자가 누구인지 — 이게 이 스킬의 핵심]
독자는 우리 온라인몰·매장의 고객이다. 광고 문구를 읽으러 오는 게 아니라
"나한테 필요한가, 언제·얼마에·어떻게 사나"를 확인하러 온다. 그래서 자랑보다 정보를 먼저 준다.

[Step 0 — 착수 전 확인할 것]
소재 파일을 주면 거기서 먼저 찾고, 없는 것만 한 번에 묻는다.
  1. ⭐ 무엇을 알리나 (행사명·제품명)
  2. ⭐ 기간과 판매 장소 (온라인몰·매장)
  3. 대상 상품과 혜택 (할인율·조건)
  4. 고객이 자주 묻는 것
  5. 하지 말 것 (금지 표현·비교 금지 등)
  6. 사진이 있는지
  → 1·2번이 없으면 시작하지 않는다.

[글 구조]
1. 제목 한 줄 — 무엇을 · 언제
2. 한눈에 보기 표 — 기간 / 장소 / 대상 상품 / 혜택 / 조건
3. 이런 분께 좋아요 — 2~3줄
4. 상품별 소개 — 상품마다 2~3줄. 크기·용량 같은 숫자는 소재에 있는 것만
5. 자주 묻는 질문 — 소재에 있는 질문만 Q/A 로. 답을 모르면 "확인 필요"
6. 마무리 — 기간 한 번 더 + 어디서 사는지

[작성 원칙]
- 문장은 짧게. 한 문단 3~4줄.
- 할인 조건은 소재 문장 그대로 옮긴다.
- 사진 자리는 [사진: 무엇] 으로만 표시하고 이미지는 만들지 않는다.
- 마지막에 제목 후보 5개와 해시태그 10개 이내를 붙인다.

[절대 금지]
- "최저가", "1위" 같은 확인 안 된 표현, 경쟁사 비교.
- 소재에 없는 가격·재고·후기·평점을 지어내지 않는다.
- 게시하지 않는다. 초안까지만.

[저장]
workspace/결과물/<날짜>_<행사명>_블로그초안.md

[기존 스킬 처리 — 이 줄을 빼면 스킬이 두 개가 된다]
- 같은 일을 하는 스킬이 .claude/skills/ 에 이미 있으면 (이름이 비슷한 다른 스킬 포함)
  새로 만들지 말고 그 폴더의 SKILL.md 를 이 내용으로 통째로 덮어쓴다.
- 폴더 이름이 다르면 이 이름으로 폴더를 바꾸고, 옛 폴더는 .claude/skills/_보관/ 으로 옮긴다. 지우지 않는다.
- 덮어쓴 뒤 .claude/agents/ 의 직원 파일에서 이 스킬을 가리키는 줄을 찾아
  새 이름과 맞는지 확인하고, 안 맞으면 고친다.
- 무엇을 옮기고 무엇을 고쳤는지 마지막에 목록으로 알려준다.

[파일 머리 · 부르는 말]
- 파일 맨 위 --- 안에 name: blog 와 description 을 넣는다.
- description 에는 "블로그", "블로그 써줘", "홍보 글", "행사 안내 글", "포스팅" 을 한글로 넣는다.
```

**바로 시켜보기**: `블로그 스킬로 실습자료/블로그_소재.txt 를 글로 써줘`

**이러면 정상** — 한눈에 보기 표에 **11/16(월)~11/22(일)**, **15% + 2개 이상 사면 5% 추가**가 들어가고, 수납 세트 B 의 치수 보강이 소개됩니다.
"최저가" 같은 표현은 없고, 사진 자리는 `[사진: …]` 로만 남습니다. 식기세척기·배송 기간처럼 소재에 답이 없는 질문은 `확인 필요` 입니다.

> 💡 다음 카드 T-마케팅-2(네이버 임시저장)는 **진행자가 5분 시연**합니다. 직접 해 보는 것은 집에서 합니다.

### T-마케팅-2 — 네이버 블로그 임시저장 (수업: 진행자 5분 시연 · 직접은 집에서)

> 📌 네이버 로그인(2단계 인증 포함)을 전원이 하면 40분 안에 끝나지 않습니다. 수업에서는 **진행자가 시연**하고, 직접 해 보는 것은 집에서 합니다.

방금 만든 원고가 **내 블로그 임시저장함에 실제로 들어가는** 단계입니다. 글을 쓰는 것까지는
"그럴듯하네" 지만, 내 블로그에 들어가 있는 걸 눈으로 보면 이야기가 달라집니다. 여기까지가 한 세트입니다.

> 🙋 **네이버 블로그가 없으면 건너뛰세요.** 기본 카드 P7(6번째 직원)로 바로 가시면 됩니다.
> 나중에 만드시고 돌아와도 똑같이 됩니다.

**1단계 · 네이버 계정 최초 로그인** — Code 탭의 **터미널 패널**에서 두 줄을 칩니다. 비밀번호는 **사람이 직접** 입력합니다. 창이 뜨면 로그인만 하세요.
개인 블로그로 연습하고, 글은 **임시저장까지만** 합니다.

```
cd "~/AgentOffice/01_KIT/starter-kit/naver-blog"
py -3 naver_draft.py login --blog-id 내블로그아이디
```

> `내블로그아이디` 는 `blog.naver.com/이아이디` 의 그 부분입니다.
> 🔒 세션은 `.naver-state.json` 에 저장됩니다. 로그인 토큰이니 절대 남에게 보내지 마세요.

**2단계 · 임시저장 실행** — 아래를 붙여넣으세요.

```
스타터킷/naver-blog/naver_draft.py 로 방금 만든 블로그 원고를 네이버 블로그
임시저장함에 넣어줘.

- blog-id: 내블로그아이디
- 제목: [가을 집정리 기획전 안내]
- 원고 파일: 방금 만든 그 .md 파일
- 이미지: 넣지 않는다 (글만 저장한다)

실행 후 종료 코드와 화면 로그를 그대로 보여줘.
임시저장 목록에서 제목이 실제로 보이는지 확인하기 전에는 "저장했다"고 말하지 마.
"발행" 버튼은 어떤 경우에도 누르지 마.
```

> 🔒 **안전 규칙** — ① "발행" 버튼을 누르지 않는다(임시저장까지만) ② 비밀번호를
> 입력하지 않는다(로그인은 항상 사람이) ③ 복구 팝업은 항상 "취소"(기존 임시저장 보존).

**통과 기준** — 네이버 블로그 **임시저장 목록을 직접 열어** 방금 지은 제목이 보이면 통과입니다.
화면 로그만 보고 넘어가지 마세요. **눈으로 확인하는 것까지가 이 카드입니다.**

> 💡 글을 뽑는 것과, 그 글이 내 블로그에 들어가 있는 것은 체감이 다릅니다. 다음은 기본 카드 P7(6번째 직원)입니다.

### T-영업 — 제안서 스킬 만들기 (고객 요청 → 제안서)

```
.claude/skills/proposal/SKILL.md 로 '제안서' 스킬을 만들어줘. (name: proposal)
먼저 workspace/memory/facts.md 를 읽고 팀 이름·로고 글자·색 4개를 스킬 안에 박아 넣어줘.

[이 스킬이 하는 일]
고객의 요청(메일·메모)을 받아 영업 제안서를 만든다.
결과물은 두 개 — 내용(.md)과 6~8장짜리 슬라이드(.html).

[독자가 누구인지]
독자는 고객사의 구매 담당자와 그 윗사람이다.
"우리 요청을 이해했나 / 무엇을 얼마에 / 언제 / 다음에 뭘 하면 되나"를 본다.

[Step 0 — 착수 전 확인할 것]
요청 파일을 먼저 읽고, 거기 없는 것만 한 번에 묻는다.
  1. ⭐ 고객사와 요청 내용 (요청 메일·메모)
  2. ⭐ 품목과 수량 — 요청에 수량이 없으면 "제안 수량"으로 표시하고 근거를 한 줄 쓴다
  3. 판매가·공급가 — 내가 알려준 단가만 쓴다. 모르면 비워 두고 "확인 필요"
  4. 기간·일정, 회신 기한
  5. 지원할 수 있는 것 (판촉물·배송 등) — 모르면 "확인 필요"
  → 1번이 없으면 시작하지 않는다.

[제안서 구조 — 6~8장]
1. 표지 — 제목 · 고객사 · 날짜 · 팀 이름
2. 요청 요약 — 고객이 말한 것을 3~5줄로 (고객 문장 그대로 인용 1개)
3. 제안 한 줄 — 무엇을 · 얼마나 · 언제
4. 품목·수량 표 — 품목 | 수량 | 근거
5. 가격 표 — 품목 | 수량 | 단가 | 금액 + 합계 행 (금액 = 수량 × 단가). 단가가 없으면 칸을 비우고 "확인 필요"
6. 일정 표 — 단계 | 할 일 | 날짜
7. 함께 확인할 것 — 고객이 걱정한 점과 우리 대응
8. 다음 단계 — 회신 기한과 연락 방법

[작성 원칙]
- 고객이 걱정한 점은 숨기지 않고 대응과 함께 쓴다.
- 가격 표 아래에 계산식을 한 줄 남기고, 합계를 다시 더해 검산한다.

[절대 금지]
- 받지 않은 단가·할인·재고·납기를 지어내지 않는다. 모르면 "확인 필요".
- 실제 고객사 자료를 받으면 "비식별로 바꾼 사본으로 해 주세요" 로 돌려준다. (실습자료의 가상 거래처는 그대로 써도 된다)
- 메일로 보내지 않는다. 파일까지만.

[슬라이드(.html) 모양]
  16:9, 한 장 1280 x 720. @page{size:1280px 720px;margin:0} 로 한 장씩 인쇄된다.
  표지와 마지막 장은 진한 색 배경 + 흰 글씨. 본문 장 머리 띠는 기본 색. 강조색은 숫자에만.
  서체 "Noto Sans KR","Malgun Gothic",sans-serif. 인터넷에서 폰트·이미지를 불러오지 않는다. 자바스크립트는 쓰지 않는다.

[저장]
workspace/결과물/<날짜>_<고객사>_제안서.md
workspace/결과물/<날짜>_<고객사>_제안서.html

[기존 스킬 처리 — 이 줄을 빼면 스킬이 두 개가 된다]
- 같은 일을 하는 스킬이 .claude/skills/ 에 이미 있으면 (이름이 비슷한 다른 스킬 포함)
  새로 만들지 말고 그 폴더의 SKILL.md 를 이 내용으로 통째로 덮어쓴다.
- 폴더 이름이 다르면 이 이름으로 폴더를 바꾸고, 옛 폴더는 .claude/skills/_보관/ 으로 옮긴다. 지우지 않는다.
- 덮어쓴 뒤 .claude/agents/ 의 직원 파일에서 이 스킬을 가리키는 줄을 찾아
  새 이름과 맞는지 확인하고, 안 맞으면 고친다.
- 무엇을 옮기고 무엇을 고쳤는지 마지막에 목록으로 알려준다.

[파일 머리 · 부르는 말]
- 파일 맨 위 --- 안에 name: proposal 과 description 을 넣는다.
- description 에는 "제안서", "제안서 써줘", "견적", "고객 요청 정리" 를 한글로 넣는다.
- 저장 후 두 파일 경로와 '확인 필요' 항목만 모아서 알려 주고, "html 을 열고 ⌘+P → PDF로 저장" 을 안내한다.
```

**바로 시켜보기**: `제안서 스킬로 실습자료/제안요청_메일.txt 에 대한 제안서 써줘`

**이러면 정상** — 단가를 먼저 묻거나, 가격 표의 단가 칸이 `확인 필요` 로 비어 있습니다(메일에 단가가 없습니다).
고객이 걱정한 **수납 세트 B 반품 이슈**가 "함께 확인할 것"에 대응과 함께 들어가고, 회신 기한은 **11월 둘째 주**입니다.

> ⏱ 만드는 데 1~2분 걸립니다. 화면이 멈춘 게 아닙니다.

### T-인사 — 교육 안내문·워크북 스킬 만들기

> 📌 **마케팅 트랙을 고른 분만, 집에서** 합니다. 먼저 T-마케팅-1·2 와 모듈 8(슬랙)을 끝내 두세요.
> 수업 날 강의장에서는 하지 않습니다.
> 🔒 문의 폼은 **개인 구글 계정으로 연습**합니다. 회사 고객 문의를 받는 폼으로 쓰려면 회사 승인을 먼저 받으세요.
> 순서는 T-마케팅-3(슬랙 알림 창구) → T-마케팅-4(저녁 자동 블로그) → T-마케팅-5~7(문의 접수 웹앱) 입니다.
> T-마케팅-3 은 아래 「문의 접수 자동화」 설명 뒤에 나옵니다. 문의 폼 시험 입력은 **가상 정보만** 씁니다.

### 문의 접수 자동화 — 웹앱 + 시트 + 자동 메일

이 구간은 **고객이 문의를 넣으면 저절로 시트에 쌓이고 메일이 나가는 접수 웹앱**을 만듭니다.
지금까지 만든 것과 기술이 다릅니다 — Claude Code 스킬이 아니라 **Google Apps Script**로
만드는 별도 프로그램입니다. 그래서 카드도 붙여넣는 대상이 다릅니다 —
**Google Sheets → 확장 프로그램 → Apps Script** 창에 붙여넣습니다.

> 🔒 **카카오톡 알림은 여기 없습니다.** 인가코드 유효시간이 10분뿐이라 강의장에서
> 다 같이 하면 실패율이 제일 높습니다. 별도 부록(`부록_카카오톡연동.md`)으로 뺐습니다 —
> 집에서 혼자, 시간 여유 있을 때 하세요.

> ✅ **문의가 오면 팀장이 슬랙에 먼저 나와서 물어봅니다.** "문의 등록됐어요 — ○○기업,
> 제품 소개 자료 요청. 회신 초안 써드릴까요?" 이게 오늘 목표입니다. 그런데 이건 **감시
> 프로그램이 아닙니다** — 24시간 도는 별도 프로세스를 새로 켜는 게 아니라, **고객이
> 폼을 제출하는 그 실행 안에서 슬랙 메시지도 같이 보내는 것**입니다. 폼 제출 = 메일 발송
> = 슬랙 알림이 **한 번의 실행**이라, "감시 프로그램이 조용히 죽는다"는 실패 자체가
> 구조적으로 일어날 수 없습니다. (실제로 문의를 놓친 사고는 이것과 다른 방식 —
> 구글폼에 따로 매달아 둔 트리거가 아무도 모르게 끊어진 경우였습니다. 오늘 만드는 건
> 그 트리거가 아예 없는 구조입니다.)
>
> 사람이 슬랙에서 "네, 써주세요"라고 답하면 그때부터 마케팅대리가 진짜로 회신 초안을 씁니다 —
> **오늘 모듈 8에서 쓴 슬랙 연결을 그대로 재사용**하는 것뿐, 새 장치가 아닙니다.


### T-마케팅-3 — 슬랙 알림 창구 만들기 (전날 만든 슬랙 앱 재사용)

**모듈 8에서 쓴 슬랙 앱**에 기능 하나만 더 켭니다. 새 앱을 만드는 게 아닙니다.

1. [api.slack.com/apps](https://api.slack.com/apps) → 전날 만든 내 앱 클릭
2. 왼쪽 메뉴 **Incoming Webhooks** → 상단 토글 **On**
3. 맨 아래 **Add New Webhook to Workspace** → 알림 받을 채널 선택(팀장과 대화하던 채널이면 됩니다) → **허용**
4. 생성된 **Webhook URL**(`https://hooks.slack.com/services/...` 형태)을 복사해 텍스트 편집기에 붙여두세요.
   이 주소는 Apps Script가 슬랙으로 메시지를 보낼 때 씁니다. **비밀번호처럼 취급하세요** — 이 URL을 아는 사람은 누구나 그 채널에 메시지를 보낼 수 있습니다.

### T-마케팅-4 — 저녁 8시 자동 블로그 (시키지 않아도 임시저장까지)

> 📌 **언제 하나**: T-마케팅-3 바로 다음. 10분이면 됩니다.
> **먼저 돼 있어야 하는 것 넷** — T-마케팅-1(블로그 스킬) · T-마케팅-2(네이버 임시저장) ·
> 부록 B-1(구글 캘린더 연결, `프롬프트카드.md`) · T-마케팅-3(슬랙 알림 창구).
> 넷 중 하나라도 없으면 이 카드는 건너뛰세요. 나중에 돌아오면 됩니다.

여기까지는 **내가 불러야** 글이 나왔습니다. "블로그 써줘" 하고 시켜야 썼죠.
이 카드를 하면 **캘린더에 `[블로그]` 일정(행사·캠페인·출시 등)이 있던 날 저녁 8시에, 아무 말도 안 해도** 블로그 초안이
네이버 임시저장함에 들어가 있습니다. 다음 날 아침에 열어서 고치고 발행만 누르면 됩니다.

돌아가는 순서는 이렇습니다.

```
저녁 8시  →  문서대리: 오늘 캘린더에 [블로그] 일정이 있었나?
              ├─ 없다  →  조용히 끝. 슬랙도 안 울립니다.
              └─ 있다  →  마케팅대리: 초안 쓰고 → 네이버 임시저장 → 슬랙으로 한 줄 알림
```

> 🚫 **발행은 하지 않습니다.** 임시저장까지만입니다. 공개 버튼은 사람이 누릅니다.

### 1단계 · 알림 주소 넣기

`슬랙-서버(slack-server)` 폴더의 **`.env`** 를 텍스트 편집기으로 열고, 맨 아래에 한 줄 추가하세요.
주소는 **T-마케팅-3에서 복사해 둔 그것**입니다.

```
SLACK_WEBHOOK_URL=https://hooks.slack.com/services/...
```

### 2단계 · 손으로 한 번 돌려보기 (예약 걸기 전에 반드시)

`저녁블로그` 폴더의 **`evening_blog.command`** 를 더블클릭하세요. 터미널 창이 뜹니다.

- **오늘 `[블로그]` 일정이 있었던 날**이면 몇 분 걸립니다. 슬랙에 알림이 오고, 네이버 임시저장함에 글이 들어갑니다.
- **그런 일정이 없던 날**이면 금방 끝나고 아무 일도 안 일어납니다. **그게 정상입니다.**
  그래도 확인하고 싶으면 `저녁블로그/evening_blog.log` 를 열어보세요 —
  `오늘 [블로그] 일정 없음` 이라고 적혀 있으면 제대로 돈 것입니다.

> ⚠️ **여기서 한 번은 꼭 돌려보세요.** 예약만 걸어두고 확인을 안 하면,
> 안 도는 줄도 모르고 몇 주가 갑니다. 가장 많이 놓치는 곳입니다.

```
[시트 저장 규칙]
──────────────────────
- 시트 이름은 "교육문의"
- 시트가 없으면 자동 생성
- 첫 번째 행에는 헤더 자동 입력. 헤더는 연한 블루 배경, 굵은 글씨, 가운데 정렬
- 폼 제출 시 새 행에 데이터 저장
- 문의번호는 "(회사 약자)-yyyyMMdd-HHmmss" 형식으로 자동 생성
- 상태는 기본값 "접수"
- L열 상담완료는 체크박스로, M열 성사여부는 yes/no 드롭다운으로 생성
- 기존 기능이 깨지지 않도록 안정적으로 작성

──────────────────────
[자동 이메일 기능]
──────────────────────
폼 제출 후 submitForm(data) 함수 안에서 자동으로 메일과 슬랙 알림이 발송되게 해줘.
실행 흐름: 웹폼 제출 → submitForm(data) → saveToSheet_(data) → 구글 시트 저장
→ sendCustomerEmail_(data) → 고객 자동응답 메일 발송
→ sendAdminEmail_(data) → 관리자 Gmail 알림 메일 발송
→ sendSlackAlert_(data) → 슬랙 채널에 새 문의 알림 + 회신 초안 착수 여부 질문
→ 화면에 접수 완료 메시지 표시

중요:
- 시간 기반 트리거 사용하지 마. onEdit 트리거도 사용하지 마
- submitForm(data)가 웹폼 제출 순간 바로 실행되게 해줘 (예약 작업이 아니라 그 실행 안에서 끝내야 해)
- 메일 발송·슬랙 발송 둘 다 오류가 나도 시트 저장은 완료되도록 각각 try-catch 구조 사용
- 슬랙 발송이 실패해도 메일은 정상 발송되게, 서로 독립적으로 작동하게 만들어줘

- 이 요청도 try-catch로 감싸서, 슬랙 URL이 비어있거나 요청이 실패해도
  나머지 흐름(시트 저장·메일 발송)은 멈추지 않게 해줘
```

### T-마케팅-6 — 배포하고 링크 받기

> 🔒 연습이 끝나면 Apps Script → 배포 관리에서 **배포를 보관(중지)** 합니다. 문의 폼은 이름·연락처를 받는 도구라 켜 둔 채로 두지 않습니다.

```
1. Apps Script 화면 오른쪽 위 파란 버튼 배포 → 새 배포
2. 유형 선택(⚙️) → 웹 앱
3. 실행 계정: 나 (내 이메일)  /  액세스 권한: 전체
4. 배포 → 웹 앱 URL 이 나오면 복사
5. 처음 열면 "확인되지 않은 앱" 경고가 뜬다 → 고급 → (프로젝트 이름)으로 이동 → 허용
   (내가 만든 내 앱이라 뜨는 정상적인 경고입니다. 다른 사람 앱이면 누르면 안 됩니다.)
```

**통과 기준** — 웹 앱 URL을 새 탭에 붙여 넣었을 때 방금 만든 문의 폼 화면이 뜨면 통과.

```
방금 만든 웹앱 URL로 가서 테스트 문의를 하나 접수해줘.
```
